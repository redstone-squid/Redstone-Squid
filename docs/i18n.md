# Translating user-facing text

Translatable strings live in `locales/<lang>/LC_MESSAGES/squid.po`, compiled
to `.mo` at build/test time. The runtime lookup is stdlib `gettext`; catalog
extraction and locale negotiation use [Babel](https://babel.pocoo.org/).

Supported locales are declared in `squid.core.i18n.SUPPORTED_LOCALES`.
Adding a locale is a content change (a new `.po` file), not a code change.

## Marking a string as translatable

Wrap the literal in `_()` from `squid.core.i18n` at the point it is
*defined* (a class constant, a docstring is not picked up automatically and
must use `discord.app_commands.locale_str` instead, see below):

```python
from squid.core.i18n import _

default_message = _("The requested operation could not be completed.")
```

Dynamic content must not be interpolated into the msgid — translate first,
then `.format(...)` the translated template:

```python
from squid.bot.i18n import t

t(locale, "Try again in {seconds:.1f} seconds.", seconds=error.retry_after)
```

Slash command names, descriptions, and choice labels use discord.py's own
`app_commands.locale_str` mechanism instead (see `squid/bot/i18n.py`'s
`SquidAppCommandTranslator`), since Discord resolves those client-side per
user before any interaction happens.

## Workflow

1. `just i18n-extract` — scans `squid/**.py` for `_()` calls and regenerates
   `locales/squid.pot`.
2. `just i18n-update` — merges new/changed msgids from the `.pot` into every
   existing `locales/<lang>/LC_MESSAGES/squid.po`.
3. Translate the new/changed (`#, fuzzy`) entries in the `.po` files by hand.
4. `just i18n-compile` — compiles every `.po` to `.mo` and prints translation
   coverage statistics.

To add a brand-new locale: `just i18n-init <locale>` (e.g. `just i18n-init
fr`), then translate and compile as above.

`.po` source catalogs are committed; compiled `.mo` files are gitignored
build artifacts (like `.pyc`), generated by `just i18n-compile` in CI and by
the Docker image build. Run `just i18n-compile` locally too, before running
tests — `tests/unit/core/test_i18n_catalogs.py` fails if a `.po` doesn't
compile cleanly or a stale `.mo` no longer matches its `.po`.
