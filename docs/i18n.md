# Translating user-facing text

Translatable strings live in `locales/<lang>/LC_MESSAGES/squid.po`, compiled
to `.mo` at build/test time. Runtime lookup uses stdlib `gettext`; catalog
extraction and locale negotiation use [Babel](https://babel.pocoo.org/).

Supported locales are declared in `squid.core.i18n.SUPPORTED_LOCALES`.
Adding a locale is a content change (a new `.po` file), not a code change.

## Authoring and resolving text

`tr` is the only application translation function. A template string creates a
deferred `Message`, which can cross domain and rendering boundaries before the
audience locale is known:

```python
from squid.core.i18n import tr

default_message = tr(t"The requested operation could not be completed.")
retry_message = tr(t"Try again in {seconds:.1f} seconds.")
```

At a text boundary, `tr(message)` resolves a deferred message using the
localization bound to the current HTTP request, command, routed control, or
background handler. Text that must be resolved immediately uses a plain string
and named parameters with the same ambient localization:

```python
detail = tr(error.message)
cooldown = tr("Try again in {seconds:.1f} seconds.", seconds=error.retry_after)
```

Plural text is deferred as one typed message. Both templates must use the same
placeholders, including an integer named `count`:

```python
count = len(builds)
summary = tr(t"{count} build", plural=t"{count} builds")
```

Slash command names, descriptions, and choice labels use
`app_commands.locale_str("...")` instead. Discord resolves those client-side
before an interaction; `SquidAppCommandTranslator` uses the same catalog.

## Workflow

1. `just i18n-extract` scans `squid/**.py` for `tr(...)` and
   `locale_str(...)` calls and regenerates `locales/squid.pot`.
2. `just i18n-update` merges new and changed msgids into each
   `locales/<lang>/LC_MESSAGES/squid.po`.
3. Translate new or changed (`#, fuzzy`) entries in the `.po` files by hand.
4. `just i18n-compile` compiles each `.po` to `.mo` and prints coverage.

To add a locale, run `just i18n-init <locale>` (for example,
`just i18n-init fr`), then translate and compile as above.

`.po` source catalogs are committed; compiled `.mo` files are gitignored build
artifacts generated by `just i18n-compile` in CI and the Docker image build. Run
the compile locally before tests: `tests/unit/core/test_i18n_catalogs.py` fails
if a catalog does not compile or a stale `.mo` differs from its `.po`.
