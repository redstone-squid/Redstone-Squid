# squid-layouts redesign series

Design-debt fixes for `packages/squid-layouts`, agreed 2026-08-21 while the framework is
still on the `local-development` feature branch. Each numbered file is one independently
landable unit of work with its own verification section; this file fixes the order and
the reasons for it.

The audit behind these plans covered the whole package (~8k lines), the nine production
consumers, and a comparison against CascadeUI
(https://github.com/HollowTheSilver/CascadeUI). Everything found is captured: plans
01–07 are the dependency-ordered core, 08–17 are agreed improvements whose order is
flexible, and `90-deferred.md` records what was consciously rejected or postponed so it
is not re-derived later.

| 39 | [Ephemeral handoff](39-ephemeral-handoff.md) | An opt-in `RenewEphemeral` mount policy replaces an expiring private panel with a protected, non-mutating renewal screen; its click adopts fresh edit authority and restores the same mount on the same message. | 40 | [Shared state](40-shared-state.md) | View state whose lifetime exceeds one mount and whose writes still belong to the action that made them: `sl.Shared[ScopeT]` namespace classes of `sl.cell()` descriptors, held and shared as ordinary objects, staged into the existing transaction, published as `(handle, descriptor)` addresses on 26's bus, and restored blindly by 28's history. A namespace holds the same `_Cell` a component does, so immutability, tracking, staging, rollback and deltas all come from the machinery `sl.state()` already uses ([41](41-reactivity-cells.md)). No store, no keyed lookup, no lifetime subsystem — the handle is the state and GC is the lifetime. Opened by fixing `transaction()`'s unrolled-back commit path. Naming a cell without reading it is `sl.addresses(lambda: handle.cell)`, which reuses the render collector rather than adding a typeless method to the handle. **Shipped.** |
| 41 | [Reactivity cells](41-reactivity-cells.md) | Replaces `sl.state()`'s mutation proxies with values that are replaced, never mutated — enforced by the type checker through overloads that declare a `dict`/`list`/`set` default as its read-only ABC — automatic read tracking in place of hand-maintained `depends=`, and pull-based computeds that recompute when a version they read has moved. No dependent lists: every reference points reader to source, so a per-message component is collected. Deletes `ReactiveList`/`Dict`/`Set`, `_observe`, `_plain`, `_Snapshot` and `CopyMode`; `copy="ref"` becomes `opaque=True`. Writes stage in the transaction's overlay, so read-your-writes survives an `await` without publishing a dirty read, and rollback is dropping the overlay. Rewrites 40 onto the same node, so a computed can depend on shared state. Undeclared transaction-time writes always raise and `strict_state()` is deleted — the lax mode was the only one that let the write land. Chosen from three prototypes in `spikes/41/`. **Shipped.** |
| 42 | [Redundant edits](42-redundant-edits.md) | Nothing in the delivery path compared a staged render against the one on screen, so a refresh scheduled by an address rather than by a difference edited Discord anyway — and every delivery rotates control ids, so an in-flight click could lose a race to a repaint that changed nothing. Design (2026-08-23): compare at the scene fingerprint with asset and handler-identity guards, split `_commit` so a suppressed render commits the tree without a new generation, never notify durability, and report `PresentationOutcome.UNCHANGED` plus reactor/mount counters so silence is distinguishable from a dead subscription. **Designed; implementation in progress.** |
| 43 | [Mount defaults](43-mount-defaults.md) | `MountDefaults` holds the host-wide half of `Mount.__init__`; `SessionRegistry` holds one and `open` accepts a component. The Cascade class-body policy surface is rejected and recorded in 90: access and scope need an actor, and one component opens under different policies. Retires the bot's `create_mount`. |
| 44 | [Migration guide](44-migration-guide.md) | `docs/migrating.md` for an existing discord.py bot, ordered by how little has to change: fragments, classic, routed controls, mounts, forms, a lifecycle mapping table. Docs only. |
| 45 | [Topic bridge](45-topic-bridge.md) | `TopicCodec` plus a host-owned `PostgresTopicBridge` over `LISTEN`/`NOTIFY` for encodable host topics — addresses, never state; `Shared` cells stay local. The render worker is the first second process. Not a relay on the bus, not a store. **Shipped.** |
| 46 | [Declarative record](46-declarative-record.md) | `sl.action(..., record=history)` records a tier-1 entry inside the action transaction; auto-recording stays rejected and 28's contract is unchanged. The binding carries the label the entry takes, so a row that collapses into a picker keeps recording. **Shipped.** |
| 47 | [Topic values](47-topic-values.md) | `type Topic = Hashable` becomes a frozen `Topic(kind, key)` value with `CellAddress` for shared-cell identities and `type Address = Topic | CellAddress` as what the bus carries — which makes encoding total, so `KindKeyCodec` ships as the bridge's default and 45's host codec demotes to an override. Phase 2 adds `sl.watch(*topics)`: a valueless versioned cell read inside a `sl.resource`, so the mount follows what its render actually read (41's thesis, applied to named topics) and 26 §B4's subscribe-before-read race and §B6's rehydration gap both close. `watch=` on `sl.resource` was designed and rejected — longer than the statement it sugars. Phase 3 deletes the bot's `follow_resource`. **Shipped.** |
| 48 | [Resource writes](48-resource-writes.md) | `Resource.replace` wrote `_state` directly, so a rolled-back action kept its replaced value and every other reader saw it before the commit -- the one write in the package that did not stage. It now joins the action through the existing `ActionParticipant` seam, with `Resource.state` reading the staged replacement back. No new primitive; `action_participant()` is just the read half of `join_action`. Unblocks 47 phase 3. **Shipped.** |
| 54 | [Resource chains](54-resource-chains.md) | A resource could not derive from another resource: reading one tracked nothing, so a dependent went silently stale, and the bot had to fuse `(build, node)` into one loader. `await self.other` inside a loader settles it, tracks it after the value is in hand, and orders the chain -- the frontend cannot discover it, because the pending set is what the *render* touched. Versions move on every transition and bump the epoch, so a computed can derive from a resource too. Cycle detection generalises to one task-local stack across computeds and resources, naming the whole ring rather than "X reads itself". Deletes 47 phase 2's `resources` parameter. **Shipped.** |
| 43 | [Candidate atomicity](43-candidate-atomicity.md) | External-review fixes at the mount's staged-candidate and lock-discipline seams: shared follows retire only on delivery, shared self-writes move the render-input revision, acknowledgement cannot wait behind a busy paint, presented hooks are synchronous under the render lock, and middleware's transaction boundary is explicit. **Shipped.** |
| 51 | [Screens](51-screens.md) | The per-open half of a session becomes a value, as 43 made the per-host half one: `Screen(name, scope, policy, access, options)` plus an `Opener` from which the access policy, `SessionKey` and `actor_id` are all derived once. `parent=` collapses the attach-or-open branch. The motivating defect is a load-bearing comment — the two consent sites keep one shared session key in sync by prose, and nothing fails a test when they drift. Class-body policy stays rejected; a screen is a value a host may build twice. |
| 52 | [Entity selects](52-entity-selects.md) | Discord's user/role/channel/mentionable pickers reach a message, not just a modal: an exact `EntitySelect` primitive plus a semantic `Entities` whose ladder degrades to author-enumerated `Choices` on a target without `actions.discord.entity` — the enumeration `settings_view.py` writes by hand today. Costs one component and one row with placeholder-only text, which is the number whose absence forced `SettingsPanel` down to one channel picker at a time. Restores 04-settings.md's five live pickers. |
| 53 | [View adoption](53-view-adoption.md) | `adopt(view)` turns an **unsent** `discord.ui.View` into a `Component`: items translate to exact primitives, the legacy object keeps its state and callbacks, and Squid is the sole writer. An interaction proxy reads `edit_message(view=self)` as "flush" and refuses every second-writer call by name. Narrows 90's rejection rather than reversing it — a live view still owns a message and stays rejected, which `adopt()` enforces. Depends on 52. |

## Relation to existing plans

`docs/plans/squid-layouts-migration.md` remains the tracker for deleting superseded
discord.py view classes. Its `primitives.presets` bullet is superseded by plan 04 here;
its "core design debts closed" list still describes the landed state this series builds
on.
